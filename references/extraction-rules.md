# 招标文件抽取规则与坑位

## 为什么"非标"是本质

政府采购、国企采购、企业自主采购各有各的模板，同一家代理机构换个项目也会改结构。所以抽取必须**基于结构特征而非固定章节号**：不假设"第四章一定是评标办法"，只认"标题里含评标/评分/评审"。

## 评分办法的四种形态

| 形态 | 特征 | 脚本处理 |
|---|---|---|
| 标准表格 | 列头含"评分因素/分值/评分标准" | 直接解析，`parse_tables` 支持 Markdown 与 docx 表格 |
| 文字叙述 | "价格分 30 分…技术分 45 分…"分段写 | 分类能识别，评分点需人工补录（会出 warning） |
| 附件表格 | 评分表在单独附件或图片里 | 抽不到。要求用户提供附件或手工转 Markdown |
| 分档描述 | "优 12–15 分、良 8–11 分" | 识别为 1 个主观评分点（不拆成 4 条） |

**核对铁律**：所有评分点分值之和必须等于声明的总分。不相等就先怀疑抽取，再怀疑文件——90% 是合并单元格。

## ★ 与 ▲ 条款

- `★`（或 `*`）：实质性条款，负偏离即废标。必须逐条在技术/商务偏离表里写"完全响应"并附证据。
- `▲`：重要条款，通常影响评分（每负偏离一项扣 N 分）。
- 有的文件用"必须""应当""不得"而不加符号——此时脚本会报 `未发现 ★ 条款`，必须人工通读资格条件与技术需求。

**易踩的坑**：废标章节里会写"未实质性响应带 ★ 号条款的按废标处理"，这句话本身含 ★，会被误当成待响应条款。脚本按章节位置排除，人工核清单时若看到这种条目，删掉即可。

## 废标条款的两种落点

1. **独立章节**："第 X 章 废标条款/无效投标情形" —— 整章都是红线。
2. **散落各处**：资格要求末尾、格式要求里（"未签字盖章的投标无效"）、报价要求里（"超预算无效"）。

脚本两路都抓，所以 A 区可能既有整章条目也有散条目，**允许重复，宁可多一条不可漏一条**。

## 形式要求（最容易被忽略、也最容易废标）

| 类型 | 典型要求 | 检查点 |
|---|---|---|
| 份数 | 正本 1 份、副本 4 份 | 副本数量、封面标注"正本/副本" |
| 密封 | 正副本一个包封、U 盘单独密封、报价文件单独密封 | 封套标注、封口盖章签字、骑缝章 |
| 签署 | 投标函/授权书法定代表人签字+公章 | 签字人是否有授权、公章是否清晰 |
| 编排 | 连续页码、目录页码与正文一致 | 排版后逐页对 |
| 电子版 | U 盘含 PDF + 可编辑格式 | 文件能否打开、是否含报价 |
| 暗标 | 技术标不得出现公司名称/标识 | 页眉页脚、图片水印都要清 |

**暗标**（技术标匿名评审）是特殊雷区：一旦技术文件出现公司名、logo、甚至特定字体，直接废标。招标文件写"技术文件不得体现投标人信息"时，必须在目录初稿的技术册备注里标红。

## 时间节点

必抓五个：获取文件截止、质疑/澄清截止、投标保证金到账、投标截止、开标。保证金到账时间通常早于投标截止 1 天，**按银行到账算而非汇出时间**。

## 抽取不到时的正确姿势

不要"凭经验补一条"。正确做法：

1. 在 `warnings` 里明确写出缺什么；
2. 让用户提供可解析的版本（转 Word、OCR、手工转 Markdown 表格）；
3. 或人工把条目补进 `parsed.json` 再跑后续步骤——`parsed.json` 就是中间格式，手改完全合法。

## 多份文件（澄清/修改/答疑）

澄清文件会改评分表、改截止时间、改★条款。处理顺序：

1. 分别解析，比对 `timeline` 与 `scoring` 差异；
2. 以最后一份澄清为准，把差异写进交付物开头"变更提示"；
3. **不要**简单拼接文本后解析——两份评分表会打架。
